[명령: 특정 기능 독립 테스트 모듈 분리]

현재 부모 파일(articles.html)에서 [분리할 기능 이름: 예: '랜덤 선택하기' 메쉬 그리드 및 위치 인디케이터] 기능만 
떼어내어 독립 테스트용 단독 HTML 파일(test_grid.html)로 새로 생성해줘.
(디버깅이 끝난 후 다시 합칠꺼야.)

[세부 규칙]
1. 경계 격리 규격 준수:
   - 스타일은 /* === [MODULE-STYLE: 기능명] === */
   - 마크업은 <!-- === [MODULE-HTML: 기능명] === -->
   - 스크립트는 // === [MODULE-SCRIPT: 기능명] ===
   위 3개 블록으로 깔끔하게 감싸서 작성해줘.
2. 독립 구동 보장:
   - 부모 화면의 복잡한 전체 로직 없이, 이 단독 파일 하나만 브라우저로 열어도 해당 기능이 온전히 작동하도록 필요한
   - 샘플 데이터(또는 필수 fetch)와 최소한의 래퍼(Wrapper)를 포함해줘.
3. 토큰 및 속도 최적화:
   - 부모의 다른 부가 기능(필터링, 교정 에디터 등)은 모두 배제하고 오직 해당 모듈의 UI/로직만 간결하게 집중 작성해줘.

  ======

 [명령: 독립 모듈 1:1 완전 치환 재병합]

독립 테스트 파일(test_grid.html)에서 검증이 완료된 코드를 부모 파일(articles.html)의 
해당 위치에 1:1 완전 교체(Replace)해줘.

[엄격 준수 규칙]
1. 블록 단위 정밀 치환:
   - CSS: articles.html의 /* === [MODULE-STYLE: 기능명] === */ 구역을 test_grid.html의 스타일로 덮어쓰기
   - HTML: articles.html의 <!-- === [MODULE-HTML: 기능명] === --> 구역을 test_grid.html의 마크업으로 덮어쓰기
   - JS: articles.html의 // === [MODULE-SCRIPT: 기능명] === 구역을 test_grid.html의 스크립트로 덮어쓰기
2. 원형 보존 원칙:
   - test_grid.html에 작성된 클래스명, 태그 순서, 인라인 스타일, 여백, 로직을 단 1글자도 임의로
     축약하거나 재해석하지 말고 100% 동일하게 이식할 것.
   - 모듈 영역 외의 기존 부모 코드(메타 태그, 탭 전환, 필터 드롭다운, 본문 뷰어, 교정 모달 등)는 절대 훼손하지 말 것.
3. 버전 및 커밋 리마크:
   - 메인 타이틀 배지 버전을 1단계 판올림하고, 파일 최상단 첫 줄에 이번 변경 사항 요약 커밋 리마크를 작성해줘.
